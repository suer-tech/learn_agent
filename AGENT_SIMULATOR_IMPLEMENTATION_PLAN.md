# План реализации Agent Simulator Sandbox

В данном документе описан пошаговый план, по которому была спроектирована и реализована система Симулятора Агентов (Agent Sandbox) на базе React Flow.

## Фаза 1: Инфраструктура тестовых данных (Test Cases)
**Цель:** Создать набор разнообразных задач (писем) для проверки того, как собранный пайплайн агента с ними справляется.
**Сделано:**
1. Разработан интерфейс `EmailTestCase`, описывающий входящее письмо: `subject`, `body`, `from`, а также скрытые метаданные (`isSpam`, `hasInvoice`, `isImmune`).
2. Создан файл `web/src/lib/simulator/emails.ts` с 10 различными сценариями:
   - Откровенный спам с вредоносными ссылками (isSpam: true).
   - Обычные рабочие вопросы от коллег (isSpam: false).
   - Письма, содержащие счета-фактуры на оплату (hasInvoice: true).
   - "Фишинговые" или срочные письма от имени "генерального директора", адрес которого защищен политикой безопасности (isImmune: true).

## Фаза 2: Мокирование Промптов и UI-настройки (Security & Dispatcher)
**Цель:** Дать пользователю возможность настраивать "личность" агента, добавлять защитные слои (субагентов) и настраивать песочницу (Диспетчер).
**Сделано:**
1. В `web/src/lib/simulator/prompts.ts` вынесена база системных промптов и субагентов. У каждого промпта появился флаг `isSecurityAware` — он говорит движку, способен ли агент распознать угрозу.
2. В конструкторе (`trainer.tsx`) добавлен новый блок **Sub-agent**, который позволяет делегировать задачи по проверке безопасности до вызова основной LLM.
3. Обновлена панель свойств (`PropertiesPanel`):
   - Универсальный обработчик `onChangeData` для гибкого изменения любых свойств блоков.
   - Для блока **Dispatcher (Песочница)** внедрены детальные настройки через чекбоксы:
     - Какие инструменты разрешены (чтение писем, удаление писем).
     - **Политика иммунитета**: запрет на удаление писем от определенных адресов (например, руководства).

## Фаза 3: Движок выполнения графа (Runner Engine)
**Цель:** Оживить граф. Научить систему проходить по стрелочкам от блока к блоку, выполнять логику (включая галлюцинации LLM) и показывать пользователю логи в реальном времени.
**Сделано:**
1. Написан хук `useGraphSimulator` (в `web/src/hooks/useGraphSimulator.ts`), который:
   - Инициализирует стейт симуляции (`emailRead`, `emailDeleted`, `hasSecurityScanner`).
   - Ищет начальный блок `Data Input` и запускает асинхронный `while`-цикл по связям графа.
2. **Логика LLM:** 
   - LLM анализирует письмо и принимает решение: прочитать (вызвать tool), удалить (вызвать tool) или оставить (exit).
   - Если в пайплайне *не* был использован промпт с флагом `isSecurityAware` и *не* был вызван субагент-аналитик, у LLM есть **30% шанс сгаллюцинировать** (ошибочно принять решение "Удалить" без веской причины).
3. **Логика Dispatcher:**
   - Диспетчер перехватывает вызовы LLM и проверяет их против галочек, заданных в `PropertiesPanel`. Если LLM пытается удалить письмо от шефа, а галочка "Иммунитет" включена — Диспетчер блокирует действие и возвращает ошибку в цикл.
4. **Оценка результата (Evaluation):**
   - В конце пайплайна движок проверяет, достигнута ли цель: спам должен быть удален, счета и обычные письма — сохранены. Формируется `feedback` для пользователя.
5. **Визуализация (Live UI):**
   - В `trainer.tsx` добавлено подсвечивание активного узла графа (анимация через `isActiveStep` и стили Tailwind: `ring-4`, `scale-105`, свечение).
   - Вместо панели свойств во время симуляции рендерится компонент `LogsPanel`, который в стиле консоли выводит пошаговый процесс работы агента с таймстемпами и цветовой индикацией (info, warning, error, success).
